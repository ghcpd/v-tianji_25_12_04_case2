- Many different shapes for user data appear across the codebase: e.g., `userId` vs `uid` vs `id` vs `identifier`, and `userName` vs `username` vs `displayName` vs `fullName`.

- Types being defined in-line across components instead of using a shared canonical type.
- Services, hooks, and components used different shapes and error handling patterns.
- No consistent use of TODO/FIXME or a labeling policy — the `.refactored` suffix appears to be an informal migration marker.

## Files I refactored (demonstration) 🔧
I standardized these files to use the canonical shape and to centralize logic:
- userService.ts → now re-exports `userService.refactored` (single service surface)
- useUserData.ts → updated to use the canonical `User` type and `fetchUserById` service
- UserTable.tsx → updated to import and use the canonical `User` type (`userId`, `userName`, `userEmail`)

These changes were intentionally conservative and designed to show a migration pathway — not a forced global change.

1. Adopt a canonical model for domain types (I used `User` with fields `userId`, `userName`, `userEmail`). Create `src/types/index.ts` to re-export that canonical type.
2. Consolidate adapters and service logic into a single location (`src/services/*` and `src/types/*` adapters).
3. Remove `.refactored` duplicates once all imports use canonical files — do this in small PRs (10–15 files per PR).
4. Add CI linting/formatting: ESLint + @typescript-eslint naming rules and Prettier.
